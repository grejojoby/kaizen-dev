/ THE CONTROL LOOP 01—05

A better start.
Five clear moves.

Not process for process’s sake. A practical sequence that keeps an agent close to the request, the real implementation, and the evidence.

  1. 01 LOOK ⌕

    Inspect first

    Read project rules, current changes, callers, and the tests that define behavior.

  2. 02 BOUND ↳

    Set the scope

    Turn the request into an observable result. Ask when a material choice is missing.

  3. 03 CHANGE ⌁

    Make it small

    Choose the smallest complete fix that matches the project’s active path and patterns.

  4. 04 VERIFY ✓

    Test what matters

    Protect meaningful behavior and risk—not a coverage number for its own sake.

  5. 05 REPORT ↗

    Show the proof

    Summarize the diff, checks, and anything that remains uncertain.

/ TEST QUALITY CONFIDENCE OVER COVERAGE

Coverage is a signal.
Confidence is the goal.

A 100% line score means every line ran. It cannot promise your assertions would catch the bug. Write a test when it gives meaningful assurance; skip it when it merely mirrors a one-line utility.

THE METRICREACHABILITY
100%

Every line executed.

Useful for finding code no test reaches. Not proof the test catches a meaningful failure.

THE QUESTIONBEHAVIOR
WOULD THIScatch a real bug?

Confidence you can explain.

Test an observable contract, edge case, or regression where the behavior matters.

— SKIP THE DUPLICATE

No direct test for a trivial trimName helper if the profile-form test already checks whitespace normalization end to end.

+ KEEP THE REGRESSION TEST

Reject report.csv.exe at the upload boundary while still accepting report.csv.

Meet documented project thresholds when required. Otherwise, add tests for the confidence they provide—not to make a percentage move.

/ PRINCIPLES, MADE PRACTICAL NO STEREOTYPES

Grounded in practice.
Built for software.

Kaizen Dev adapts ideas associated with Japanese manufacturing and reflection practices. They’re prompts for the work—not claims about how every Japanese developer codes.

Read the principles and sources ↗
01 / GO SEE

Genchi genbutsu 現地現物

Inspect the real code path. Gather evidence before deciding what to change.

02 / IMPROVE

Kaizen 改善

Make a small, durable improvement. Leave unrelated cleanup for another time.

03 / MAKE VISIBLE

Jidoka 自働化

Surface failed checks and investigate them. Never relabel a failure as success.

04 / REFLECT

Hansei 反省

Reflect when it can produce a concrete process improvement, not extra ceremony.
