THE PRACTICE02 — 06

One loop. Five steps.
No guesswork.

Not more process for its own sake. A short sequence that keeps the agent close to the request, the code, and the evidence.

  1. 01

    Look

    Read instructions, current changes, callers, and the tests that define the behavior.

    BEFORE WRITING
  2. 02

    Bound

    Turn the request into an observable result. Ask only when a real decision is missing.

    NO SCOPE CREEP
  3. 03

    Change

    Make the smallest complete fix that follows the active path and the project’s own patterns.

    ONE CLEAR MOVE
  4. 04

    Verify

    Test behavior and risk—not coverage for its own sake. Treat failures as evidence; show what you checked.

    SHOW THE RESULT
  5. 05

    Report

    Summarize the diff, checks, and uncertainty in plain language.

    NO HIDDEN GAPS
TEST QUALITYCONFIDENCE OVER COVERAGE

Chase confidence.
Not 100%.

Coverage can reveal code no test reaches. But a perfect line score cannot prove a test would catch a real regression. Choose tests for behavior, contracts, and risk—not for the percentage alone.

— SKIP THE DUPLICATE

+ KEEP THE REGRESSION TEST

Find what runs.
Fix that.

Agents can find three helpers named “retry” and still pick the wrong one. Kaizen Dev asks them to trace callers from the entry point, confirm the helper is actually used, then read the tests before the first edit.

ROOTED IN PRACTICENOT A STEREOTYPE

Four principles.
One better loop.

These ideas are adapted from Japanese manufacturing and reflection practices for software work. They are not claims about how every Japanese developer writes code.

A

Genchi genbutsu

現地現物

Go to the actual source. Trace real callers and read the tests instead of guessing from names.

SEE WHAT RUNS ↗
B

Kaizen

改善

Improve in small, complete steps. Avoid rewriting the surroundings to fix one behavior.
